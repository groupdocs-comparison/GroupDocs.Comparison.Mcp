# 26.7.0 — Engine 26.5.0, shared ToolError, Docker MS-core-fonts, unique solution GUIDs

## What changed
- Bumped `GroupDocs.Comparison` engine from 26.4.0 to 26.5.0 (latest stable; under `net10.0` the MCP resolves the new `GroupDocs.Comparison.Net100` sub-package). SkiaSharp pin stays `3.119.0` — that is exactly what `Net100` 26.5.0 declares transitively, so no ABI change.
- Bumped the MCP package version from 26.5.2 to 26.7.0 (CalVer), including `.mcp/server.json` (both `version` fields), README, and `llms.txt` install pins.
- Extracted the duplicated per-class `FormatException` helpers from `CompareTool` and `GetDocumentInfoTool` into a single shared `Tools/ToolError.cs` (`ToolError.Format(op, file, ex, subjectSuffix)`). Output text is byte-for-byte identical to before — `Compare failed for '<source>' vs '<target>': …` and `Document-info lookup failed for '<file>': …` — so integration-test prefixes are unaffected.
- `docker/Dockerfile`: added `ttf-mscorefonts-installer` (with debconf EULA pre-accept + `fc-cache`) alongside the existing `libgdiplus`/`libfontconfig1`. The `compare` tool re-renders text glyphs into its marked-up output; without MS core fonts the engine failed on font resolution on Linux containers (Pitfall #17). The Tests repo's `integration.yml` already installed these fonts — the Dockerfile was the gap.
- `src/GroupDocs.Comparison.Mcp.sln`: regenerated all four solution GUIDs. The `src` and `tests` solution-folder GUIDs had been copied verbatim from the Metadata template, and the two project GUIDs were sequential placeholders; all are now freshly generated and unique.

## Why
Keeping the engine current picks up upstream comparison fixes; the shared error helper removes ~10 lines of duplicated formatting per tool and keeps the failure contract in one place; the Docker font fix makes containerised `compare` runs render correctly on Linux; unique GUIDs avoid solution-identity collisions with the Metadata template.

## Migration / impact
Drop-in replacement for 26.5.2. No tool-name, input-schema, or response-shape changes. Failure-prefix text is unchanged.
